# Job Copilot — Devpost draft

## Elevator pitch

Privacy-first Chrome extension that matches résumés on-device, sends only approved sections to cloud AI, autofills applications, and tracks outcomes.

## Project story

### Inspiration

Job seekers repeatedly share the same sensitive information across application sites and often upload an entire résumé just to answer one narrow question. Job Copilot explores a safer approach: keep routine matching and decision support on the user's computer, make every cloud handoff visible, and send only the professional section needed for the task.

### What it does

Job Copilot is a Chrome side-panel extension built around two explicit AI paths. It reads a user-reviewed job page and compares up to five locally stored résumé variants with Gemini Nano on-device, labeling the verified result `ON DEVICE`. It can also scan visible application fields, preview local candidate-vault matches, and fill only after approval without overwriting answers or submitting. When stronger cloud reasoning is useful, the user supplies only relevant job requirements, one résumé section, and verified evidence. The extension shows that exact payload before consent. Only after approval does Firebase AI Logic rewrite the selected section and label the result `IN CLOUD`. The extension never silently falls back from local AI to cloud AI.

The hackathon MVP makes the privacy boundary visible across résumé matching, application autofill, local outcome tracking, selective cloud tailoring, and local DOCX export.

### How we built it

The project is a Manifest V3 Chrome extension written in TypeScript. Firebase AI Logic provides both hybrid inference paths: `ONLY_ON_DEVICE` for Gemini Nano in Chrome and `ONLY_IN_CLOUD` for the consented section rewrite. Firebase App Check is registered and enforced. Structured response schemas validate the résumé recommendation and section patch before either result is shown. A production build, private debug build, automated privacy/parser tests, and a five-file judge ZIP are generated by the repository scripts.

### Challenges

The largest challenge is App Check inside a packaged Manifest V3 extension. The normal web provider loads a Google script that Chrome's extension content-security policy blocks. Development is verified with a private registered App Check debug token, which the hackathon rules accept for judging, while the public repository and production ZIP contain no token. We also had to account for computers without Gemini Nano and prevent any automatic cloud fallback.

### Accomplishments

- Downloaded and ran Gemini Nano in Chrome for a real `ON_DEVICE` résumé comparison.
- Completed a consent-gated `IN_CLOUD` section rewrite through Firebase AI Logic.
- Enforced Firebase App Check and verified the registered debug-token exchange.
- Made the inference source and minimized cloud payload visible in the interface.
- Kept identity, contact, citizenship, sponsorship, clearance, veteran, disability, demographic, and EEO data out of the cloud request.
- Added user-reviewed local autofill that excludes demographic and EEO questions, preserves existing answers, and never submits.
- Added a local application tracker with duplicate prevention and explicit outcome updates.
- Added fail-closed local DOCX generation that changes only the approved section in a downloaded copy.
- Added automated validation for prompt privacy, response binding, unknown résumé rejection, and fractional score normalization.

### What we learned

Hybrid AI is most valuable when users can understand and control the boundary, not merely when an SDK chooses a model. A visible consent step, a clear inference badge, and a no-silent-fallback rule turn an implementation detail into a product promise.

### What's next

Next we will harden installation and judge fallback testing on computers without Gemini Nano. We will keep identity and demographic answers local by default and continue sending only the smallest approved professional payload to cloud AI.

### Main technology requirement response

Job Copilot uses Firebase AI Logic for both required inference paths in a Manifest V3 Chrome extension. `ONLY_ON_DEVICE` runs résumé matching with Gemini Nano in Chrome and verifies that the returned inference source is `ON_DEVICE`. `ONLY_IN_CLOUD` is a separate user-approved flow that sends only the displayed job requirements, one selected résumé section, and verified professional evidence to the Gemini Developer API, then verifies the result source is `IN_CLOUD`. A fictional payload is available for judge testing. Firebase App Check is registered and enforced. The extension never silently falls back from local to cloud AI.

### Private judge-testing note

Install the organizer-provided private judge build as an unpacked Chrome extension. Confirm Gemini Nano status, run **Analyze on device**, and verify the badge reads **ON DEVICE**. Choose **Load fictional judge demo**, open **Review exact cloud request**, inspect the minimized payload, choose **Keep it local** once, then reopen and approve it to verify the badge reads **IN CLOUD**. If Gemini Nano is unavailable, the extension must state that nothing was sent to the cloud. The private App Check debug token will be provided only through Devpost testing instructions and is not present in the public repository or production ZIP.
